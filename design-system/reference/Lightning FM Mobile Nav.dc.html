The header at phone width

Finding 10 asked for every nav item to stay reachable on mobile, and the implementation delivered that with flex-wrap. Five links plus the theme icon need about 750px, so below that they wrap to three rows — and because the header is sticky, that block follows you down the page. A hamburger keeps the promise of finding 10 without spending a third of the viewport on it.

Why 860

Measured, not guessed: the five links come to roughly 515px, the lockup 140px, the theme icon 44px, plus gaps — about 750px before it wraps. 860 leaves headroom for a sixth link without anyone revisiting this. Note that Tailwind's md is 768px and would still wrap; this needs a custom stop.

The panel pushes the page down rather than floating over it. No overlay, no scrim, no scroll lock — with five links it is short enough that the page underneath is still context, not clutter.

The theme icon stays in the bar. It is 44px, it costs nothing to leave out in the open, and burying a preference two taps deep to save that space is a bad trade.

"Start selling" stays a plain row. The amber fill belongs to the hero CTA alone — that rule holds on mobile, where the two would otherwise sit 60px apart.

Implementation notes

It belongs in SiteHeader, not the homepage

Build this inside the shared shell from SITE_SHELL.md, not in Landing.tsx. Every page inherits the mobile nav the moment it adopts the shell — and if the shell does not exist yet, this is a second reason to build it first.

The toggle carries state, the panel carries an id

aria-expanded on the button, aria-controls pointing at the panel's id, and an aria-label that names the action — "Open menu" / "Close menu". The glyph swaps bars for a cross; do not animate the morph.

Close on Escape, on navigation, and on resize past the breakpoint

The last one is the easy miss: open the panel at 500px, rotate to landscape, and without it you get an open mobile panel underneath a full desktop nav. Return focus to the toggle when Escape closes it.

The desktop nav stays exactly as it is

Above 860px nothing changes — same five links, same theme icon last, same 44px targets. Render one nav or the other at the breakpoint rather than restyling a single list, so the mobile rows are real 56px targets instead of desktop links with extra padding.

Client component

SiteHeader becomes "use client" once it holds open state — it already would, since ThemeSwitcher is a client component. Keep SiteFooter a server component; it has no state.
